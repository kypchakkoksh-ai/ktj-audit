# Аудит ТС — КТЖ / Самрук-Қазына

Полноценный сайт (Next.js) для аудита технической спецификации (ТС) на соответствие
Порядку закупок АО «Самрук-Қазына», Правилам взаимодействия СП АО «НК «ҚТЖ» и
постатейному чек-листу. В отличие от прежней версии-артефакта, здесь нет ограничения
в 1000 токенов на ответ модели — резюме и весь чек-лист (37 пунктов) собираются за 2 запроса.

## Что умеет сайт

- Загрузка ТС на русском и/или казахском языке (.docx / .txt), сверка их идентичности.
- Ручная сверка кода ЕНСТРУ: вы находите код на enstru.kz сами и вписываете в поле —
  агент сверяет его с кодом в ТС и в Плане закупок.
  **Почему не автоматически:** enstru.kz запрещает автоматический доступ в своём
  robots.txt, публичного API у портала тоже нет — легально автоматизировать эту
  проверку нельзя.
- Загрузка Плана закупок (.xlsx / .xls) — сверка наименования, характеристик,
  единиц измерения, объёмов, доп. характеристик.
- Загрузка отдельного файла требований к поставщику (опционально — по умолчанию
  агент сам ищет этот раздел в конце текста ТС).
- Загрузка дополнительных нормативных документов (ГОСТ, СТ РК и т.п.), если ТС
  ссылается на что-то, чего нет во встроенной базе.
- Отчёт: резюме, счётчики рисков, детализация замечаний, постатейный чек-лист
  (статус «Соответствует / Не соответствует / Недостаточно данных» + рекомендация).
- История проверок сохраняется в браузере (localStorage).

## Технически

- Next.js 14 (App Router), без базы данных.
- `app/api/audit/route.js` — серверная функция, которая проксирует запросы к
  Gemini API (`generativelanguage.googleapis.com`), используя ключ из переменной
  окружения `GEMINI_API_KEY`. Ключ никогда не попадает в браузер.
- Модель по умолчанию — `gemini-2.5-flash` (бесплатный тариф Google AI Studio,
  ~10 запросов/мин, ~250 запросов/день на момент написания — этого хватает на
  десятки проверок ТС в сутки, поскольку один аудит = 2 запроса).
- `mammoth` — извлечение текста из .docx на клиенте.
- `xlsx` (SheetJS) — разбор Excel-плана закупок на клиенте.

## Деплой на Vercel

1. Установите [Node.js 18+](https://nodejs.org) локально (для проверки перед деплоем — опционально).
2. Получите **бесплатный** ключ Gemini API:
   - откройте https://aistudio.google.com/apikey,
   - войдите через Google-аккаунт (без привязки карты для бесплатного тарифа),
   - нажмите **Create API key**, скопируйте ключ (начинается с `AIza...`).
3. Загрузите содержимое этой папки в свой GitHub-репозиторий (или используйте Vercel CLI
   без GitHub — см. пункт 5).
4. На [vercel.com](https://vercel.com) → **Add New → Project** → импортируйте репозиторий.
5. Либо через CLI, из этой папки:
   ```bash
   npm install -g vercel
   vercel
   ```
6. **Обязательно** добавьте переменную окружения в настройках проекта на Vercel
   (Project → Settings → Environment Variables):
   ```
   GEMINI_API_KEY = AIza...
   ```
   Без неё серверная функция вернёт ошибку 500.
7. Передеплойте проект после добавления переменной (Vercel → Deployments → Redeploy),
   переменные окружения подхватываются только при новой сборке.

## Локальный запуск

```bash
npm install
cp .env.example .env.local   # впишите свой ключ в .env.local
npm run dev
```
Сайт будет на http://localhost:3000

## Про бесплатный тариф Gemini

- Ключ создаётся без банковской карты — https://aistudio.google.com/apikey.
- Лимиты бесплатного тарифа периодически меняются у Google (обычно в районе
  10 запросов/мин и пары сотен в день для Flash-моделей) — если увидите ошибку
  429 (`rate_limit`/`quota`), подождите минуту или проверьте текущие лимиты в
  Google AI Studio → ваш проект → Rate Limits.
- Квоты считаются на уровне проекта Google Cloud, а не ключа — если создадите
  несколько ключей в одном проекте, они делят один и тот же лимит.
- Если бесплатного лимита перестанет хватать — включите биллинг в том же
  проекте Google AI Studio, ничего в коде сайта менять не придётся.

## Важные ограничения

- **enstru.kz** — только ручной ввод, без автоматического доступа (сайт запрещает
  роботам доступ через robots.txt, публичного API у портала нет).
- **SAP и prg.kz** — не подключены; в чек-листе нет пункта сверки с
  номенклатурой SAP (исключён по вашему запросу).
- Требования к поставщику по умолчанию читаются из текста самой ТС — отдельный
  файл нужен, только если требования оформлены отдельным документом.
- Модель, используемая для аудита — `gemini-2.5-flash`, задаётся в
  `app/api/audit/route.js` (константа `MODEL`).
